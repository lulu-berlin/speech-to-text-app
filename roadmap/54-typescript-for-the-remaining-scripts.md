## Goal

The scripts written before ADR 0054 follow it: every hand-written JavaScript file outside item 50
becomes TypeScript, run directly by Node (type stripping) or compiled where its syntax needs it, and
its package's test command type-checks it with `tsc --noEmit`. No behavior changes.

## Proposal

1. Convert each file to `.ts` with types, keeping its behavior, output text and exit codes.
   Imports between the scripts name their `.ts` files (`allowImportingTsExtensions`), and the
   documentation checks run as `node docs/check-links.ts …` (Node type stripping).
2. The documentation checks get their own package: `docs/package.json` (`typescript`, `@types/node`,
   `prettier`; own `pnpm-lock.yaml`), `docs/tsconfig.json` (`strict`, `noUncheckedIndexedAccess`,
   `erasableSyntaxOnly`, `verbatimModuleSyntax`, `noEmit`), and
   `pnpm --dir docs test` = `tsc --noEmit` + the three checks (the green commands over
   `README.md` and `docs/architecture.md`) + `check-exceptions` and its `node --test`.
   `docs/check-readme-windows.mjs` is converted and joins them once item 49 has merged.
3. `e2e/` gets one `e2e/tsconfig.json` that replaces `e2e/desktop/tsconfig.json` and includes the
   harness, `global-setup.ts`, `check-playwright.ts`, the Playwright configs, `desktop/`, the
   desktop specs and all journey specs. `pnpm --dir e2e test` runs `tsc -p tsconfig.json`; the six
   `test:desktop*` scripts and the two CI steps that name `desktop/tsconfig.json` follow.
4. Update every caller: AGENTS.md § Commands, `e2e/package.json`, `e2e/playwright*.config.ts`,
   `docs/architecture.md` (`e2e/global-setup.mjs` → `.ts`), `devenv.nix`'s comment,
   `docs/check-architecture-names.mjs`'s e2e extension filter (`.mjs` → `.ts`), the CI `docs-check`
   job (install and run the docs package), and the `desktop/tsconfig.json` paths in CI.
5. Type the converted e2e clip list as a tuple so the specs' `FIXTURE_CLIPS[n]` accesses stay
   `string`, then fix the remaining annotations the probe found — no behavior change.

## Decided (consultation, 2026-10-22)

- **Sequencing**: the spec is approved now, but the work starts in its own worktree only after item
  49 has merged. Item 49 is in-progress and edits the same files (AGENTS.md, README.md, `ci.yml`,
  the e2e process harness) and adds `docs/check-readme-windows.mjs`; running in parallel would mean
  rebasing conflicts and converting a file that does not exist yet. The item therefore depends on 49.
- **Docs package** (open question a): its own `docs/package.json` with a lockfile, like
  frontend/e2e/desktop, rather than reusing e2e's TypeScript or a root tsconfig. A root tsconfig
  would need hand-written ambient `node:` declarations (no root `@types/node`) and CI's `docs-check`
  job does not run the devenv.
- **e2e scope** (open question b): the one `e2e/tsconfig.json` includes the existing specs now, not
  only the converted scripts — ADR 0054 says each package's test command checks its TypeScript, and
  the probe shows the fix is mostly one tuple annotation plus ~18 real annotations, with no behavior
  change.
- **`docs/check-exceptions.ts`/`.test.ts`** are part of the docs package's type check (they are TS
  with no tsconfig today).
- **No new app e2e** (ADR 0046 exemption, stated because the roadmap's rule requires one per
  feature): this item changes no app behavior; the existing journey suite is a must-not-break item
  instead.

      (actionlint clean)
