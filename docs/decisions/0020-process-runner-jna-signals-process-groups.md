# 0020 — Process runner: JNA signals, process groups, cancellation

Status: accepted · Date: 2026-10-06

## Context
The backend must run external tools (ffmpeg, whisper-cli). ADR 0004 requires pausing the current whisper-cli process with `SIGSTOP` and resuming with `SIGCONT`. Java exposes no signal API: `Process.destroy()`/`destroyForcibly()` send `SIGTERM`/`SIGKILL` to the direct child only, and there is no way to set a process group before exec (`posix_spawn` does it, but JDK does not expose the flag). ADR 0001 requires all async work on coroutines. Command failure must surface exit code and stderr; long runs stream output line by line.

## Decision
- `stt/process/ProcessRunner` (Kotlin): `suspend fun run(cmd, onStdoutLine = {}, onStderrLine = {}): ProcessResult(exitCode, stdout, stderr)`. Callbacks stream each line as it is written; the result captures both streams (stdout for order/amount, stderr for error messages).
- Every command is spawned as `setsid <cmd…>` (util-linux): the run owns a fresh session and process group, and the direct child's pid is the group id (in the normal case setsid execs the command without forking). All signals target the group (negative pid), so the whole process tree — not just the direct child — is stopped, resumed, and killed.
- Signals are sent with JNA `kill(2)` (`com.sun.jna.Native.load("c", …)`): `pause()` = `SIGSTOP` to the group, `resume()` = `SIGCONT`. No `kill` binary is spawned. Signal numbers are the Linux constants (SIGSTOP 19, SIGCONT 18, SIGTERM 15, SIGKILL 9); the app targets the Linux Nix build.
- Cancellation of the caller kills the tree: `SIGCONT` first (harmless if not stopped; lets a signal handler run its cleanup), then `SIGTERM`, wait the grace period, then `SIGKILL`, then `run` returns by rethrowing `CancellationException`.
- Grace period between `SIGTERM` and `SIGKILL` defaults to 2 s; it is a constructor parameter (integration tests inject a short grace).
- Cancellation is observed via 50 ms `waitFor` polling with `ensureActive()` (blocking waits themselves are not interruptible). Buffered but undelivered lines are dropped: the drain coroutines are children of `run` and are cancelled.
- stdout and stderr are drained concurrently by two child coroutines on `Dispatchers.IO` so a full pipe buffer never blocks the child; callbacks must be non-blocking.
- `pause()`/`resume()` are no-ops when the process has already exited (`Process.isAlive()` guard; `kill(2)` errors ignored — the pid-reuse race is accepted).
- Non-existent executables fail fast: the executable is resolved against PATH before spawning, and `start()` IOExceptions are wrapped in `ExecutableNotFoundException` whose message names the command.
- Blocking I/O and waits only inside `withContext(Dispatchers.IO)`; no raw `Thread`, `ExecutorService`, or `CompletableFuture`.
- Output is line-oriented. Binary stdout (e.g. ffmpeg raw PCM) is out of scope; the audio item reads files or adds a byte mode.
- The runner is single-flight (one active process, matching the queue that processes one task at a time); `pause()`/`resume()` address the current run. The Java 21 `setsid` edge case — the spawned child already being a process-group leader, causing setsid to fork and pid ≠ group id — does not occur under the JVM and is not engineered around.

## Consequences
- New explicit dependencies: `org.jetbrains.kotlinx:kotlinx-coroutines-core` (1.11.0) and `net.java.dev.jna:jna` (5.14.0, already transitive via Ktor's tree). `backend/deps.json` is regenerated by the user and `nix build .` re-verified.
- The dev environment and the packaged app need `setsid` (util-linux) on PATH; item 16 extends the wrapper environment. Added to `devenv.nix` in this item (ADR 0010).
- One tiny extra exec per run (setsid); signals cost no processes.
- Test determinism requires no fixed sleeps for synchronization; bounded waits/timeouts everywhere.
- Rejected: coreutils `kill` spawn (extra process per signal, PATH dependency), `Process.destroy()` for cancel (direct child only, not the tree), returning `Flow<String>` for stdout (an uncollected flow fills the pipe and stalls the child), draining to EOF on cancel (slower, can hang on lingering pipe holders).
