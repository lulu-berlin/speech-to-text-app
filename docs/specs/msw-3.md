# 91 — MSW 3: the API mocks, the shared handlers and the dev worker

Status: done (roadmap item 91, approved 2026-11-06)
Depends on: [13](frontend-foundation.md) (done; the MSW server and the shared handler set)
Blocks: —

## Goal

The frontend mocks every API endpoint with MSW 3 (currently 2.15.0), so the whole suite and the
mocked development server keep serving the `docs/api/` contract examples unchanged, and no MSW 2 API
or config remains.

## Evidence

- **One handler set, one server for the tests**: `frontend/src/shared/api/handlers.ts` holds the
  handlers for every item 12 endpoint and the SSE stream, serving the contract examples in
  `docs/api/` (ADR 0029); `frontend/src/test/server.ts` builds one `setupServer(...handlers)` that
  `frontend/src/test/setup.ts` starts and resets, and tests override per case with `server.use`.
  Fifteen source files import `http`/`HttpResponse` from `msw`.
- **The app itself runs MSW in development**: `frontend/src/mocks/browser.ts` (`setupWorker(...)`),
  the generated `frontend/mock/mockServiceWorker.js`, served at the origin root by
  `frontend/vite.config.ts:24`; `frontend/package.json`'s `msw.workerDirectory` names `mock`, so the
  worker script is generated by MSW and must be regenerated for the new major.
- **The SSE mock is hand-rolled**: MSW's `sse()` types only unnamed events while the contract needs
  named ones, so `handlers.ts` writes the frames itself into a `ReadableStream` response; that
  construction has to be re-checked against v3's `HttpResponse` behaviour (headers, cancellation,
  early end).
- **The upgrade is real**: `frontend/package.json` pins `msw` 2.15.0; latest on npm is **3.0.3**
  (checked 2026-11-04). It is a major with test-time and dev-time surface.
- **What 3.x changes for this code** (MSW's 2.x → 3.x migration guide): Node ≥ 22 (the app runs
  24); `http`/`HttpResponse` move from `msw` to `msw/http`, so the fifteen importing files change
  their import path; `server.listen`'s `onUnhandledRequest` is renamed `onUnhandledFrame`
  (`frontend/src/test/setup.ts:39`); `setupServer` (`msw/node`) and `setupWorker` (`msw/browser`)
  keep their entrypoints; `worker.stop()` now returns a Promise. The GraphQL and WebSocket changes
  do not apply (neither is mocked here). 3.x also offers an `msw/vite` plugin that serves the worker
  without a committed script.

## Decided (consultation, 2026-11-04)

- Filed at the user's request from the dependency scan; a major, so its own item rather than a lock
  bump.
- The mocked data remains the `docs/api/` contract examples (ADR 0029); this item changes the mock
  library, not the contract.
- **Exact pin** (the repository's convention for `msw`): `msw` is pinned to an exact 3.x version.
- **Keep the committed worker** (the user): `frontend/mock/mockServiceWorker.js` is regenerated with
  3.x through the same `msw.workerDirectory` field, and Vite keeps serving it; the `msw/vite` plugin
  is not adopted in this item. The test list's "no MSW 2 … config" means no 2.x-only option (such as
  `onUnhandledRequest`); the `workerDirectory` field stays, because 3.x's `msw init` reads it.
- **Exempt from ADR 0046's per-feature e2e test** (the user): the item changes the test and dev-mock
  tooling, not an app feature; the frontend suite and the existing journeys are its proof.

## Proposal

1. Read MSW's v3 migration notes and inventory the surface in use: `setupServer`, `setupWorker`,
   `http.*`, `HttpResponse`, `server.use`, the worker script/config, and the manual SSE response.
2. Pin `msw` exactly to 3.0.3 (or the then-current 3.x, exactly) and regenerate the worker script
   into `frontend/mock/` through the same `workerDirectory`, keeping the Vite serving path.
3. Port the shared handlers and the per-test overrides to v3; keep every response identical to the
   `docs/api/` example, including the "Mock addition" cases item 13 records.
4. Keep the SSE behaviour the specs exercise: named events in order, `retry`, optional heartbeat and
   end, and the client's watchdog reaction.

None. (Settled 2026-11-04, see "Decided (consultation, 2026-11-04)".)

## Test list

- [x] (basic) The whole frontend suite passes with MSW 3: every spec that mocks an endpoint serves
      the same status, headers and body as before.
- [x] (basic) Per-test overrides (`server.use`) still take precedence and reset between tests.
- [x] (basic) The SSE mock still delivers named events in order, honours `retry`, the heartbeat and an
      early end, and the client's watchdog behaves as its specs expect.
- [x] (basic) `pnpm dev:mock` serves the regenerated worker at `/mockServiceWorker.js` and the app's
      requests resolve through it.
- [x] (edge) An unmatched request behaves as it does today under the configured
      `onUnhandledRequest` policy.
- [x] (edge) A handler that throws, and a stream that ends early, surface the same client behaviour
      as before.
- [x] (must not break) No MSW 2 import or `msw` config remains, and the `docs/api/` examples are
      unchanged by this item.
- [x] (must not break) With mocking off, the Vite dev proxy still serves the real backend.

Discovered in the root agent's review of 2026-11-06 (approved by the user the same day):

- [x] (discovered) The suite fails when the pinned @mswjs/interceptors is not the copy msw itself
      resolves, so a future msw bump cannot leave two copies installed silently.
- [x] (discovered) The dev-proxy test passes with a service holding port 8080: it runs its stand-in
      on a free port and still checks the dev config proxies /api to http://localhost:8080.

## e2e stance

Exempt from ADR 0046's per-feature e2e test (decided 2026-11-04): the item changes the mocking
tooling, not an app feature, and the existing suites and journeys running unchanged are its proof.
